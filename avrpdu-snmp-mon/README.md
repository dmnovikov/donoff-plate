# donoff-pdu-view

Страница для АВР и управляемых PDU по SNMP: вводы АВР, розетки, маленькие графики на плитках,
полные графики по клику, история в InfluxDB 2. Один статический бинарник, работает на плате NAPI
рядом с устройством.

Сейчас есть профиль **RCNTEC RPCM** (АВР на 2 ввода и до 10 управляемых розеток). Другие модели
добавляются файлом профиля, без правки кода.

## Что делает

- Опрашивает устройство SNMP GET (v2c): АВР и вводы раз в 2 с, розетки раз в 5 с, имена, пороги
  и систему раз в минуту.
- Показывает:
  - плитку АВР: напряжение, частота, ток, мощность и энергия каждого ввода, какой ввод активен,
    приоритетный ввод, земля, текущая мощность и энергия всего;
  - плитки розеток: вкл/выкл, мощность, ток, энергия, аварии;
  - маленькие графики за 24 ч (напряжение вводов, ток розеток), клик по ним открывает полные
    графики за 15 мин – 7 дн;
  - карточку «Об устройстве»: описание модели из профиля, серийный номер, прошивка, что читается.
- Пишет историю в InfluxDB 2 раз в 10 с (без InfluxDB: только плитки, без графиков).
- Управляет только розетками из `-control`, и не чаще `-min-gap` (10 с) и `-max-hour` (20 в час)
  на розетку. Без `-control` программа только читает.

## Запуск

```sh
donoff-pdu-view -host 192.168.0.78 -community public -listen :8095 -control 1
```

| Флаг | По умолчанию | Что |
|---|---|---|
| `-host` | (нужен) | адрес устройства, `host` или `host:port` (порт SNMP 161); старое имя `-rpcm` |
| `-community` | public | community SNMP v2c |
| `-profile` | auto | id профиля или `auto`: по sysObjectID устройства |
| `-profiles` | | папка с дополнительными профилями `*.yaml` (тот же id заменяет встроенный) |
| `-list-profiles` | | показать профили и выйти |
| `-main` | 1 | какой ввод АВР основной |
| `-listen` | :8095 | адрес страницы |
| `-control` | | розетки, которыми можно управлять: `1` или `1,3` |
| `-min-gap` | 10s | наименьший промежуток между переключениями одной розетки |
| `-max-hour` | 20 | больше всего переключений одной розетки за час |
| `-name` | pdu1 | имя устройства в InfluxDB (тег `dev`) |
| `-influx-url` | http://127.0.0.1:8086 | InfluxDB 2 |
| `-influx-org`, `-influx-bucket` | nnz, pdu | организация и бакет |
| `-influx-token-file` | /etc/donoff-pdu-view/influx.token | файл с токеном (только токен или `token=...`) |

Память: сама программа около 9 МБ, `GOMEMLIMIT` 24 МБ. Графики берутся одним запросом за раз и
кэшируются, на линию не больше 400 точек.

Токен InfluxDB кладётся в файл (только root): только токен или строка `token=...`. В
репозитории токенов нет. В InfluxDB измерения называются `rpcm_ats`, `rpcm_input`, `rpcm_outlet`
(так с первой версии, чтобы история не терялась), устройство различается тегом `dev`.

## API

- `GET /api/state`: всё текущее, вместе с профилем (`profile.has`: что есть у модели).
- `GET /api/history?what=ats&range=30m`, `what=outlet&n=1`, `what=spark` (24 ч для плиток).
- `POST /api/outlet` с `{"n": 1, "on": 0}` и `Content-Type: application/json`: переключить розетку
  (403 нельзя, 429 слишком часто).

## Профиль модели

Файл YAML: описание устройства и где у модели лежат значения. `{n}` в OID заменяется номером
ввода или розетки. Чего нет в профиле, того нет на странице и в истории.

```yaml
id: vendor-model                 # для -profile
vendor: Vendor
model: Model
title: Vendor Model — АВР и PDU  # заголовок страницы
description: |                   # описание устройства: карточка «Об устройстве»
  Что это за устройство, сколько вводов и розеток, что меряет, чем управляется.
links: [https://vendor.example]
match: [.1.3.6.1.4.1.NNNN.X]     # префиксы sysObjectID для -profile auto

system:                          # всё необязательно
  model:    {oid: ..., type: text}
  serial:   {oid: ..., type: text}
  firmware: {oid: ..., type: text}
  name:     {oid: ..., type: text}
  location: {oid: ..., type: text}
  temp:     {oid: ...}
  uptime:   {oid: ..., scale: 0.01}   # в секундах после множителя

ats:                             # нет АВР: inputs: 0 (или нет раздела)
  inputs: 2
  first: 1                       # номер первого ввода
  active:   {oid: ...}           # номер активного ввода
  priority: {oid: ...}
  failback: {oid: ...}
  ground:   {oid: ..., yes: 1}   # значение «земля в норме»

input:                           # по одному на ввод, {n} = номер ввода
  name:     {oid: "...{n}", type: text}
  present:  {oid: "...{n}", yes: 1}   # есть ли напряжение
  hz:       {oid: "...{n}", scale: 0.01}
  v:        {oid: "...{n}"}
  ma:       {oid: "...{n}"}
  w:        {oid: "...{n}"}
  kwh:      {oid: "...{n}", type: string}   # число строкой
  inverted: {oid: "...{n}", yes: 1}   # фаза перепутана
  vmin:     {oid: "...{n}"}
  vmax:     {oid: "...{n}"}

outlets:
  count: 8                       # или count_oid: {oid: ...}
  first: 1                       # индекс первой розетки в SNMP (0 или 1)
  name:  {oid: "...{n}", type: text}
  admin: {oid: "...{n}"}         # что задано
  on:    {oid: "...{n}"}         # что на самом деле
  ma: {oid: "...{n}"}
  w: {oid: "...{n}"}
  va: {oid: "...{n}"}
  var: {oid: "...{n}"}
  kwh: {oid: "...{n}", type: string}
  alarms:                        # авария, когда значение равно yes (по умолчанию 1)
    - {oid: "...{n}", label: КЗ}
  switch: {oid: "...{n}", on: 1, off: 0}   # без switch розетки только читаются
```

Поле: `oid`, `type` (`int` по умолчанию, `string` — число в тексте, `text` — текст), `scale`
(множитель), `yes` (для состояний), `label` (для аварий).

Встроенный пример: [`profiles/rcntec-rpcm.yaml`](profiles/rcntec-rpcm.yaml).

Новая модель:
1. Взять MIB устройства и прочитать нужные OID: `snmpget -v2c -c public <адрес> <oid>`.
2. Написать профиль, положить в папку `-profiles` (или в `profiles/` и пересобрать).
3. `donoff-pdu-view -profiles <папка> -list-profiles`, затем запустить с `-profile <id>` или `auto`.
